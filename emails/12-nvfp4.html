NVIDIA's Blackwell architecture (RTX 5090 and beyond) introduces native hardware support for FP4 — 4-bit floating point computation. CuteDSL already supports it. Here is what that means for inference performance.

What is NVFP4?

NVFP4 is NVIDIA's 4-bit floating point format, supported natively by the Blackwell GPU tensor cores. Unlike software-emulated INT4 quantization, NVFP4 operations run at full hardware speed with dedicated FP4 tensor core instructions. Each value uses just 4 bits — half the size of INT8 — while the floating point format preserves more dynamic range than fixed-point alternatives.

Benefits

Memory 4x smaller than FP16, 2x smaller than INT8. Fit larger models on a single GPU.
Speed Blackwell tensor cores process FP4 at 2x the throughput of FP8, translating to significantly faster matrix multiplications.
Quality Floating point format preserves outlier weights better than INT4, maintaining model accuracy.

torchao Integration

CuteDSL uses torchao (PyTorch Architecture Optimization) to handle NVFP4 quantization. The integration is seamless — torchao quantizes model weights to FP4 at load time, and the Blackwell tensor cores handle the rest. No changes to model code are required.

How to Enable

If you are running the CuteDSL inference server on an RTX 5090 or other Blackwell GPU, enable NVFP4 with a single environment variable:

# Enable NVFP4 quantization for Blackwell GPUs
ENABLE_NVFP4=1 make inference

# Or set it in your environment
export ENABLE_NVFP4=1
python inference/server.py

The server will automatically detect Blackwell hardware and apply FP4 quantization to all supported model weights. On non-Blackwell GPUs, the flag is safely ignored.
